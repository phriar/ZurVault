# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ZurVault (zurvault.com) is a static site for browsing and viewing a Solana NFT comic-book collection (DC Comics digital comics minted on-chain, largely via candy.io). There is no build step, no package manager, and no server-side code — every page is a single self-contained `.html` file with inline `<style>` and `<script>`. Deployment is just serving these files as static assets (e.g. GitHub Pages, per `CNAME`).

## Running locally

There's no dev server or build command. Open the HTML files directly in a browser, or serve the directory statically, e.g.:

```
python3 -m http.server 8000
```

There is no test suite, linter, or formatter configured in this repo.

## Pages

- `index.html` — landing page. Neon hero marquee (wordmark glow built off the site's own violet/cyan tokens, not a separate color) with "See Latest Drops" / "Browse Dollar Bins" CTAs, then the live Magic Eden listings + recent sales feed across all known DC sub-collections (`DC_COLLECTIONS` array of `{sub, symbol}` pairs defined inline), fetched from the Worker's `GET /v2/dc-summary` (see below) rather than calling Magic Eden per-collection itself. Has a Grid/List view toggle (see below).
- `characters.html` / `character.html` — a directory of characters (Batman, Superman, etc., from `character-map.js`, hand-curated) and a templated per-character page (`character.html?c=batman`) showing that character's For Sale / Recently Sold, filtered from the same `/v2/dc-summary` data `index.html` uses. Also has the Grid/List toggle.
- `collections.html` / `collection.html` / `collections-map.js` — same pattern, but grouped by comic series/imprint instead of character (`collection.html?s=bat-cowl`). Some entries are mechanically matched by `sub` prefix (e.g. everything starting with "Absolute"), others hand-curated; a few entries also carry a `history` write-up and a curated `keyIssues` list (first appearances, landmark issues) rendered on the page. `blurb`/`history`/`keyIssues` text is a first draft, not verified fact — see the file header.
- `artists.html` / `artist.html` / `artist-map.js` — same pattern again, grouped by cover artist (`artist.html?a=jim-lee`). Unlike `character-map.js`/`collections-map.js`, this one is **fully mechanical, not hand-curated** — generated by querying Magic Eden's per-collection listings endpoint for every `DC_COLLECTIONS` symbol and reading the `Cover Artist` trait off one sample listing (valid because Cover Artist is constant across an entire print run, unlike Rarity — see below). It's a point-in-time snapshot: regenerate it the same way if `DC_COLLECTIONS` changes. `artists.html` has a text filter box (177 entries).
- `dollar-bin.html` — cross-collection "cheapest first" browse across every tracked collection at once (price-bucket pills, sorted ascending), instead of checking ~200 collection pages one at a time. Grid/List toggle; List view shows the mint/edition number parsed out of the listing name where present.
- `rarity.html` — cross-collection browse filtered by rarity tier (Common/Uncommon/Rare/Epic/Legendary), same color-coded badges as `slideshow.html`. **For Sale only** — Magic Eden's activities endpoint (what sold items are derived from) doesn't carry `token.attributes`, so sold items have no rarity captured. Depends on a `rarity` field in `/v2/dc-summary` listings that `me-proxy-worker.js` only started populating recently — **see the pending-Worker-redeploy reminder below**.
- `spotlight.html` / `spotlights-data.js` — templated long-form write-up page (`spotlight.html?id=...`) for curated pieces about a specific comic.
- `guide.html` — static "how to buy on Magic Eden, then read on candy.io" walkthrough.
- `discover.html` — a tooling page (not linked from primary nav) that scans a wallet's owned assets via Helius, groups them by on-chain collection, and attempts to resolve each to a Magic Eden symbol so the result can be pasted into `index.html`'s `DC_COLLECTIONS` array (and `me-proxy-worker.js`'s copy — see below). Entries that fail to resolve are marked `UNRESOLVED_<mint-prefix>` and need manual lookup on Magic Eden.
- `slideshow.html` — connects to a Phantom wallet (or a `?wallet=` kiosk address, see Configuration in README.md) and presents the collection as an auto-advancing fullscreen slideshow (`INTERVAL`, currently 10s) — meant for reusing an old tablet as a physical "cover frame" display. Shows a color-coded rarity badge (Common/Uncommon/Rare/Epic/Legendary) pulled from the NFT's own on-chain `Rarity` attribute where present, normalized client-side since different candy.io drops format that trait inconsistently (`CORE` as an alias for Common, a `(NN.NNN)` weight suffix on some drops, etc.) — see `rarityTierKey()`.
- `comics.html` — a standalone client-side comic reader. Accepts drag-and-drop images/CBZ/CBR (unpacked in-browser via JSZip) or a comic loaded from a URL query param (`?url=...&title=...`). candy.io is the primary reading experience going forward; this remains as a standalone fallback.
- `candy-watcher.html` — a Solana transaction watcher/dashboard. Polls RPC for mint activity, flags assets by URI pattern (`candy.io`, `api.candy.io`, etc. via `CANDY_PATTERNS`) or Arweave-hosted metadata, and highlights "seeded" update authorities. Has a backfill mode for scanning a historical date range in batches.
- `me-proxy-worker.js` — source for the Cloudflare Worker (`zurvault-proxy.stholt.workers.dev`). **In this repo, but not auto-deployed** — pushing to GitHub only updates the static pages via GitHub Pages; the Worker itself is redeployed by hand (paste into the Cloudflare dashboard). See README.md for the full configuration/deploy story, and the reminder below for what's currently pending.

## Architecture notes

- **Some shared code, most pages still standalone.** `site-nav.js` (top banner), `character-map.js`, `collections-map.js`, `artist-map.js`, and `spotlights-data.js` are genuinely shared includes. Beyond that, each HTML file still duplicates its own CSS and JS — when fixing a bug or updating a pattern (a fetch helper, a status-indicator widget, a card renderer, the Grid/List toggle), check whether the same pattern exists in other files, since they're not kept in sync automatically. `index.html`, `character.html`, `collection.html`, `artist.html`, `dollar-bin.html`, and `rarity.html` all currently share near-identical `.card`/`.list-row` CSS and a `parseEdition()`/rarity-badge helper — if you fix a bug or improve one, check the others.
- **Magic Eden calls go through a proxy, and the ~200-collection scan runs server-side.** Direct browser calls to Magic Eden's API are CORS-blocked, so pages route through a Cloudflare Worker at `https://zurvault-proxy.stholt.workers.dev` (`ME_PROXY_BASE`/`ME_BASE` constants). No page loops through collections client-side — the Worker's `scheduled()` Cron Trigger does that itself (see `me-proxy-worker.js`), writing one KV entry per collection, and `GET /v2/dc-summary` merges them into the response every listings-consuming page reads (`index.html`, `character.html`, `collection.html`, `artist.html`, `dollar-bin.html`, `rarity.html`).
- **Solana RPC calls go directly to Helius**, not through the proxy. `slideshow.html` hardcodes a Helius API key in a `HELIUS_KEY` constant; `candy-watcher.html` and `discover.html` instead prompt the user to paste their own key into an `<input type="password">` (kept session-only, not persisted).
- **`DC_COLLECTIONS` is duplicated by hand** in `index.html` (drives the sub-collection filter UI instantly) and `me-proxy-worker.js` (the Cron Trigger needs its own copy). Entries with a `symbol` starting with `UNRESOLVED_` are intentionally skipped (no confirmed ME symbol yet) — resolve these via `discover.html` and update both copies. Non-DC entries (MLB/sports-card promos that had snuck in) were removed from both copies; if `discover.html` ever resolves something that isn't actually a DC comic, don't add it here.
- **Three different curation styles for the "browse by X" maps** — worth knowing which is which before editing one: `character-map.js` is hand-reviewed judgment calls (which symbols "belong" to a character, plus a curated highlight list); `collections-map.js` mixes mechanical prefix-matching (e.g. "Absolute") with hand-written `history`/`keyIssues` text; `artist-map.js` is fully mechanical, regenerated from live Magic Eden data rather than edited by hand — don't hand-edit individual entries in it, regenerate the whole file instead (see its header for the method).
- **Rarity is a per-token attribute, not a per-collection one** — unlike Character/Artist/Series, which are the same for every copy of a given issue, Rarity (Common/Uncommon/Rare/Epic/Legendary) varies copy-to-copy within the same collection, so it can't be captured in a static hand-curated map the way artist/character groupings can. It has to come from live per-listing data. Different candy.io drops format the raw trait inconsistently (bare `"EPIC"`, `"Common (40.400)"` with a rarity-weight percentage, `"CORE"` as one drop's name for the base tier) — both `slideshow.html` (client-side, `rarityTierKey()`) and `me-proxy-worker.js` (server-side, `normalizeRarity()`) independently normalize this the same way; keep them in sync if the normalization logic changes.
- Visual style is consistent across pages (dark background, violet accent palette `--gold`/`--deep`/`--cyan`, monospace + serif font pairing, subtle noise/grain overlay) but most pages still define their own CSS from scratch rather than sharing a stylesheet. Small/low-opacity text (collection labels, timestamps, mint numbers) has a real WCAG AA contrast bar to clear (4.5:1 for anything under 18px) — when adding new small text, check it against the `#0a0a0a` background rather than eyeballing it; see the accessibility comment blocks in `index.html`/`character.html`/`collection.html`/`dollar-bin.html` for the computed reference values already in place.
