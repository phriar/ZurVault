# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

ZurVault (zurvault.com) is a static site for browsing and viewing a Solana NFT comic-book collection (DC Comics digital comics minted on-chain, largely via candy.io). There is no build step, no package manager, and no server-side code — every page is a single self-contained `.html` file with inline `<style>` and `<script>`. Deployment is just serving these files as static assets (e.g. GitHub Pages, per `CNAME`).

## Running locally

There's no dev server or build command. Open the HTML files directly in a browser, or serve the directory statically, e.g.:

```
python3 -m http.server 8000
```

There is no test suite, linter, or formatter configured in this repo.

## Pages

- `index.html` — landing page. Neon hero marquee (wordmark glow built off the site's own violet/cyan tokens, not a separate color) with "See Latest Drops" / "Browse the Back Issue Bin" CTAs, then the live Magic Eden listings + recent sales feed across all known DC sub-collections (`DC_COLLECTIONS` array of `{sub, symbol}` pairs defined inline), fetched from the Worker's `GET /v2/dc-summary` (see below) rather than calling Magic Eden per-collection itself. Has a Grid/List view toggle (see below).
- `collections.html` / `collection.html` / `collections-map.js` / `character-map.js` — two ways to browse on one page: a "Series" tab (`collections-map.js`, mixing mechanical `sub`-prefix matching like everything starting with "Absolute" with hand-written `history`/`keyIssues`, plus a few entries — batman, wonder-woman, green-lantern, aquaman — derived from `character-map.js`'s own curation instead, because `DC_COLLECTIONS`' `sub` field is inconsistently formatted for those characters; see `collections-map.js`'s header) and a "Characters" tab (`character-map.js`, hand-reviewed judgment calls, absorbed from the retired `characters.html`/`character.html`, Batman/Superman/etc. with a curated `highlights` list). The detail page handles both `collection.html?s=bat-cowl` and `collection.html?c=batman`, normalizing into one render path (Grid/List toggle, For Sale/Recently Sold tabs). `blurb`/`history`/`keyIssues`/`highlights` text is a first draft, not verified fact — see the file headers.
- `artists.html` / `artist.html` — grouped by cover artist (`artist.html?a=Jim%20Lee`, matched on the artist's exact name, not a slug). **Not a static map** — an earlier version used one (`artist-map.js`, since deleted), generated by sampling one listing per collection on the assumption Cover Artist was constant across a print run the way Character/Series is. That assumption turned out wrong: collections with variant covers (e.g. `batman_2016_158`) carry several different Cover Artist credits *within the same collection*, so the static map wrongly attributed every variant's listings to whichever artist the one sample happened to have. Now built the same way `long-box.html`'s rarity filter is — live, per-listing, off each listing's own `coverArtists` field (see `extractCoverArtists()` in `me-proxy-worker.js`). `artists.html` aggregates the directory from live data at load time and has a text filter box.
- `long-box.html` — displayed as **"Back Issue Bin"** in the nav and on-page (renamed from "Long Box" 2026-08-22 — filename, URL, and nav `id` all stayed `long-box`/`long-box.html`, this was a display-name-only change, done to avoid brand collision with ZurCovers' own "Long Box" feature, which means something different there: a wallet's own held collection, not a marketplace browse). Cross-collection "cheapest first" browse across every tracked collection at once: searchable min/max SOL price range, a name/sub-collection search, and a rarity tier filter (Common/Uncommon/Rare/Epic/Legendary, color-coded badges), sorted ascending, instead of checking ~200 collection pages one at a time. **Rarity tier is For Sale only** — Magic Eden's activities endpoint (what sold items are derived from) doesn't carry `token.attributes`, so sold items have no rarity captured. Grid/List toggle; List view shows the mint/edition number parsed out of the listing name where present. Absorbed the standalone `rarity.html` page once this page covered everything it did — that page no longer exists, don't re-add a link to it.
- `dollar-bin.html` — the simpler, original "cheapest first" browse this site launched with, revived by user request on 2026-08-10 after `long-box.html` (its own later evolution — see git history, they were literally the same file before a rename) replaced its 3 preset price buttons with a full min/max search + rarity filter. Deliberately minimal by design, not a stale duplicate: just "Under 0.05/0.1/0.25 SOL" quick-filter pills and a Grid/List toggle, no name search, no rarity filter — a fast "grab something cheap" page sitting next to the Back Issue Bin's more powerful one. Built on the Back Issue Bin's current hardened baseline (favicons, `esc()` escaping, `data-track` click attributes, the `.me-tag` "Magic Eden ↗" cue), not the original pre-hardening file. Cross-linked with `long-box.html` and `index.html`.
- `spotlight.html` / `spotlights-data.js` — templated long-form write-up page (`spotlight.html?id=...`) for curated pieces about a specific comic.
- `guide.html` — static "how to buy on Magic Eden, then read on candy.io" walkthrough.
- `discover.html` — a tooling page (not linked from primary nav) that scans a wallet's owned assets via Helius, groups them by on-chain collection, and attempts to resolve each to a Magic Eden symbol so the result can be pasted into `index.html`'s `DC_COLLECTIONS` array (and `me-proxy-worker.js`'s copy — see below). Entries that fail to resolve are marked `UNRESOLVED_<mint-prefix>` and need manual lookup on Magic Eden.
- **Slideshow feature — currently removed entirely, not just unlinked.** Google Safe Browsing flagged the original version under "Deceptive pages" — a visible wallet-address input next to a "Connect Phantom" button structurally resembles wallet-drainer phishing kits to their classifier, even though the feature was 100% read-only. It was first replaced with a static "Coming Back Soon" placeholder (`slideshow.html`) while the old implementation (Phantom connect, `?wallet=` kiosk mode, auto-advancing fullscreen display, color-coded rarity badge via `rarityTierKey()`) lived on unlinked at `slideshow-legacy.html`. After a second, unrelated Safe Browsing flag on 2026-08-09, both files were pulled from the repo entirely (unlinked from `site-nav.js`'s `PAGES` array and deleted, not just left unreferenced) rather than kept reachable at their own direct URLs, and archived locally outside the repo. Neither `slideshow.html` nor `slideshow-legacy.html` currently exist in this repo. Don't recreate the feature without addressing the underlying UI pattern first.
- `comics.html` — a standalone client-side comic reader. Accepts drag-and-drop images/CBZ/CBR (unpacked in-browser via JSZip) or a comic loaded from a URL query param (`?url=...&title=...`). candy.io is the primary reading experience going forward; this remains as a standalone fallback.
- `candy-watcher.html` — a Solana transaction watcher/dashboard. Polls RPC for mint activity, flags assets by URI pattern (`candy.io`, `api.candy.io`, etc. via `CANDY_PATTERNS`) or Arweave-hosted metadata, and highlights "seeded" update authorities. Has a backfill mode for scanning a historical date range in batches.
- `me-proxy-worker.js` — source for the Cloudflare Worker (`zurvault-proxy.stholt.workers.dev`). **In this repo, but not auto-deployed** — pushing to GitHub only updates the static pages via GitHub Pages; the Worker itself is redeployed by hand (paste into the Cloudflare dashboard). See README.md for the full configuration/deploy story, and the reminder below for what's currently pending.

## Architecture notes

- **Some shared code, most pages still standalone.** `site-nav.js` (top banner), `character-map.js`, `collections-map.js`, and `spotlights-data.js` are genuinely shared includes. Beyond that, each HTML file still duplicates its own CSS and JS — when fixing a bug or updating a pattern (a fetch helper, a status-indicator widget, a card renderer, the Grid/List toggle), check whether the same pattern exists in other files, since they're not kept in sync automatically. `index.html`, `collection.html`, `artist.html`, `long-box.html`, and `dollar-bin.html` all currently share near-identical `.card`/`.list-row` CSS and a `parseEdition()`/rarity-badge helper — if you fix a bug or improve one, check the others.
- **Magic Eden calls go through a proxy, and the ~200-collection scan runs server-side.** Direct browser calls to Magic Eden's API are CORS-blocked, so pages route through a Cloudflare Worker at `https://zurvault-proxy.stholt.workers.dev` (`ME_PROXY_BASE`/`ME_BASE` constants). No page loops through collections client-side — the Worker's `scheduled()` Cron Trigger does that itself (see `me-proxy-worker.js`), writing one KV entry per collection, and `GET /v2/dc-summary` merges them into the response every listings-consuming page reads (`index.html`, `collections.html`, `collection.html`, `artist.html`, `long-box.html`, `dollar-bin.html`).
- **Solana RPC calls go directly to Helius**, not through the proxy. `candy-watcher.html` and `discover.html` prompt the user to paste their own key into an `<input type="password">` (kept session-only, not persisted). No page currently makes Solana RPC calls to display a wallet's own NFTs — see the slideshow note above.
- **`DC_COLLECTIONS` is duplicated by hand** in `index.html` (drives the sub-collection filter UI instantly) and `me-proxy-worker.js` (the Cron Trigger needs its own copy). Entries with a `symbol` starting with `UNRESOLVED_` are intentionally skipped (no confirmed ME symbol yet) — resolve these via `discover.html` and update both copies. Non-DC entries (MLB/sports-card promos that had snuck in) were removed from both copies; if `discover.html` ever resolves something that isn't actually a DC comic, don't add it here.
- **Two curation styles feeding one merged pair of pages, plus a live-only third** — worth knowing which is which before touching one: `character-map.js` is hand-reviewed judgment calls (which symbols "belong" to a character, plus a curated `highlights` list); `collections-map.js` mixes mechanical prefix-matching (e.g. "Absolute") with hand-written `history`/`keyIssues` text, plus a handful of entries (batman, wonder-woman, green-lantern, aquaman) derived from `character-map.js`'s own symbol lists instead — `DC_COLLECTIONS`' `sub` field turns out to be inconsistently formatted even within a single series, so a literal prefix match silently drops real members for those four; see `collections-map.js`'s header for the full story. Both maps now feed the same `collections.html` (Series/Characters tabs) and `collection.html` (`?s=`/`?c=`) pair rather than two separate page pairs. Cover Artist and Rarity have **no static map at all** — both vary per individual listing rather than per collection, so `artists.html`/`artist.html` and `long-box.html`'s rarity filter are built live off `/v2/dc-summary` the same way. Before building a new "browse by X" page, check whether the underlying attribute is actually constant across a collection (safe for a static map, like Character/Series) or varies per token (needs the live approach) — guessing wrong here is exactly what caused the Cover Artist bug.
- **Rarity and Cover Artist are per-token attributes, not per-collection ones** — unlike Character/Series, which are the same for every copy of a given issue, both vary copy-to-copy within the same collection (Rarity by design; Cover Artist wherever a collection has variant covers), so neither can be captured in a static hand-curated map the way character/series groupings can — both have to come from live per-listing data. Rarity: different candy.io drops format the raw trait inconsistently (bare `"EPIC"`, `"Common (40.400)"` with a rarity-weight percentage, `"CORE"` as one drop's name for the base tier) — `me-proxy-worker.js` (server-side, `normalizeRarity()`) normalizes this once for every page that reads `/v2/dc-summary`. Cover Artist: multi-artist credits (e.g. `"Jim Lee, Scott Williams, Alex Sinclair"`) are split into individual names by `extractCoverArtists()` — same name-suffix handling as the deleted `artist-map.js`'s generator had (`", Jr."` stays attached to the preceding name).
- Visual style is consistent across pages (dark background, violet accent palette `--gold`/`--deep`/`--cyan`, monospace + serif font pairing, subtle noise/grain overlay) but most pages still define their own CSS from scratch rather than sharing a stylesheet. Small/low-opacity text (collection labels, timestamps, mint numbers) has a real WCAG AA contrast bar to clear (4.5:1 for anything under 18px) — when adding new small text, check it against the `#0a0a0a` background rather than eyeballing it; see the accessibility comment blocks in `index.html`/`collections.html`/`collection.html`/`long-box.html` for the computed reference values already in place.
