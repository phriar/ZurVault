Sealed Packs

Every currently-listed Pack across every tracked DC collection, sorted cheapest first. Packs aren't their own collection — "Pack" is an item type that shows up alongside individual comics within a collection's own listing pool, so this page filters live across all of them rather than tracking a separate catalog.

For Sale only. Magic Eden's sales/activity data doesn't carry item-type attributes the way live listings do, so a "Recently Sold Packs" view isn't possible from what this site currently tracks.

The Pack Odds tab estimates what rarity tier you'd pull from each series' Packs, from live Magic Eden listing data — it is not official candy.io pack-fill data. Full explanation of the source and method is pinned at the top of that tab.

Pack Odds
⚠ Where these odds come from — read before trusting a number

Nothing here is official. ZurVault has no access to candy.io's actual pack-fill configuration. Every bar below is inferred from the same live Magic Eden listing/sales data every other page on this site reads — no other source.

"Declared" tiers (green badge) use a rarity-weight percentage some candy.io drops publish directly on the trait itself (e.g. "Legendary (4.8)") — that's the drop's actual configured print-run split, not something we computed. None of the tracked series currently publish this.

"Print Run" tiers (cyan badge, the usual case) — each copy's name carries a serial number like (92/500), and it turns out the "500" isn't the whole issue's print run, it's specific to that one rarity tier: every "Rare" copy of a given issue shares the same total, every "Epic" copy shares a different (usually smaller) total, and so on. Once we've seen just one copy of a tier — For Sale or already Sold, it doesn't matter which — we know that tier's real planned size, and tier size ÷ sum of all tiers' sizes is a genuine odds figure grounded in the mint's own numbering, not a guess from market activity. This is why a Legendary that sold out in one minute doesn't skew the number the way a pure "what's currently listed" estimate would.

Where Print Run can still be wrong: some series have variant covers or bonus/insert items that get their own separate numbering pool within what's nominally the same tier — when that happens the tiers can sum to more than the series' advertised total edition count, inflating every percentage slightly. We haven't found a way to detect this automatically yet, so treat Print Run as "grounded in real mint data" rather than "certified exact."

"Estimated" tiers (purple badge) are the fallback for a series where no copy's name carries a parseable serial number at all, so there's no print-run total to anchor to. The bar falls back to (items of this tier currently listed) ÷ (all non-Pack items currently listed) — the old, market-activity-based estimate, with the same bias Print Run exists to avoid: it measures what hasn't sold, not the true pack-fill rate.

"Limited data" (red badge) means too little data exists to compute any of the above for that series.

See something that looks wrong? The raw counts are printed next to each bar — check them against Magic Eden's own listings for that series and flag it.
